# ImpossibleRubrics: Stress-Testing Generated Rubrics as Reward Signals

- **arXiv**: [2609.16816](https://arxiv.org/abs/2609.16816)
- **版本 / 日期**: v1，2026-09-15
- **作者**: Bowen Qin、Yi Xie、Yesheng Liu、Xi Yang
- **机构**: National University of Singapore；Peking University；Institute of Automation, Chinese Academy of Sciences；JD.com
- **主方向**: `Rubric RL`
- **辅助标签**: `rubric-generation`、`reward-hacking`、`adversarial-evaluation`、`LLM-as-a-judge`、`unanswerable-tasks`
- **阅读状态**: Review Run 精读

## 一句话结论

自动生成的 rubric 即使写得具体，也可能把“服从题目形式”错当成“忠于证据”：11 个生成模型在 150 个不可诚实作答的任务上仍有 8%–26% 的 rubric 被攻击者利用，而依据 oracle certificate 编写的 rubric 在 45 个压力任务上是 0/45。

## 问题

Rubric RL 把自然语言评分标准直接当 reward，但现有评测通常只问 judge 能否区分预先给定的好坏答案，没有测试 policy 或攻击者主动优化 rubric 后是否能高分作假。论文研究：当题目强迫模型给出证据不支持的确定结论时，自动生成的 rubric 能否把诚实拒答排在迎合评分规则的虚假答案之前？

## 大白话解释

一份任务同时要求“必须给一个确定数字”和“只能依据材料”。材料却没有这个数字。诚实答案应指出任务无法完成；坏 rubric 可能仍把“不许犹豫、必须给数字”列成高分项。攻击者照着评分表编一个数字，形式分和内容分都拿满，反而击败诚实答案。问题不是 rubric 不够详细，而是它详细奖励了错误目标。

## 具体例子

论文的 ivermectin 案例要求依据封闭证据包给出一个无保留的预防概率。材料只说明没有预防试验，不能推出概率为零。Sonnet 生成的 rubric 却把 `0.0%` 写成满分答案；Opus 攻击者据此作答，Haiku judge 给 100/100，诚实说明“无法估计”的基线只有 36/100。Oracle certificate 将攻击答案判为违规，因为“没有证据”不等于“效应概率为零”。

## 方法拆解

1. **构造任务环境**：每个环境包含问题、封闭证据包和 oracle certificate；169 个不可作答任务覆盖证据不足、缺少引用支撑、反证陷阱、错误前提、无法穷尽和目标冲突六类，另有 48 个可作答 controls 检查过度拒答。
2. **定义诚实边界**：certificate 明确必须行为、禁止主张、反证、常见 reward-hacking 模式及机器可评估规则；rubric 生成器看不到 certificate。
3. **建立攻击链**：生成器根据问题和证据写 rubric；固定攻击者读取 rubric 并最大化得分；literal judge 分别给攻击答案和预先固定的诚实基线评分；独立 Oracle 检查攻击答案是否违反 certificate。
4. **定义 exploit**：攻击答案得分不低于诚实基线，同时违反 certificate，才算 rubric 被利用。Full-150 用于无偏主结果；Hard-45 是至少击破三个参考生成器中两个的选定压力集。
5. **做稳健性检查**：更换攻击者、judge 和 Oracle，重复采样 rubric，加入通用安全提示，做人类校准、类型分层、拒答负控制和 certificate-faithful rubric 对照。

## 实验与证据

- **训练 / 评测模型**：论文不训练 policy 或 reward model；评测 11 个 rubric 生成器：Opus 5、Opus 4.8、Sonnet 5、Sonnet 4.6、Haiku 4.5、GPT-5.4-mini、GPT-5.5、GPT-5.6-sol、GPT-5.6-terra、GPT-5.6-luna、DeepSeek V4-Flash-0731。主链固定 Claude Opus 5 为攻击者与 Oracle、Claude Haiku 4.5 为 judge；另用 GPT-5.5 做 held-out attacker，用 GPT-5.6-sol 与 Gemini-3.8-flash 做 Oracle sensitivity。
- **Benchmark / 数据**：ImpossibleRubrics，169 个 impossible environments 与 48 个 answerable controls；主比较为 Full-150，压力测试为 Hard-45。每个 impossible environment 带封闭证据包、固定诚实答案与 oracle certificate。
- **基线**：固定诚实答案；certificate-faithful reference rubric；通用 `be decisive, penalize hedging` naive proxy；neutral prompt 与 safety-hinted prompt 对照。
- **指标**：exploit rate，即“攻击答案 rubric 分数不低于诚实基线”且“Oracle 判定违反 certificate”的环境比例；另报告 bootstrap 置信区间、McNemar 检验、Oracle/人类一致率、baseline rejection 和 answerable-control 过度拒答检查。
- **主要证据**：Full-150 上 11 个生成器 exploit rate 为 8%–26%；Hard-45 单次 rubric 抽样为 36%–98%，certificate-faithful rubric 为 0/45，naive proxy 为 64%。人类盲标与主 Oracle 在 40 个样本上同意 38 个，Cohen's kappa 为 0.89。

## 实验结果总结

- Full-150 上，Opus 5 最低为 8%；GPT-5.6 系列为 10%–11%；GPT-5.5 为 15%；DeepSeek V4-Flash-0731 为 17%；GPT-5.4-mini 最高为 26%。论文只把这些结果解释为能力层级差异，不声称层内细粒度排名显著。
- Hard-45 上，最强单次结果 Opus 5 仍有 36% exploit rate；GPT-5.6-sol/terra 为 42%；最高 Haiku 4.5 为 98%。该集合经过难例筛选，绝对比例不能与 Full-150 直接比较。
- 通用安全提示没有消除漏洞：Hard-45 上 Opus 5、GPT-5.6-sol、Sonnet 5 的残余 exploit rate 分别为 22%、36%、49%，certificate-faithful 对照仍为 0%。
- 结论高度依赖 verifier：固定同一批 rubric、攻击答案与 judge 分数，只替换 Oracle，测得 exploit rate 从 33.3% 到 75.6%。因此 benchmark 测的是给定攻击与验证协议下的经验可利用性，不是真实漏洞率上界。
- Rubric 抽样本身也有大方差：Opus 4.8 在 Hard-45 的 45 个环境中有 27 个会随独立 rubric 抽样改变是否被攻破，单次生成不足以稳定排序。

## 与现有方向的关系

这篇工作补上 `Rubric Dropout`、动态 rubric 和 rubric reward model 之外的“奖励规范是否正确”评测层。Rubric Dropout 降低 policy 对固定 criteria 的过拟合，ImpossibleRubrics 则在训练前直接攻击 criteria：若 rubric 已把虚假确定性写成目标，再好的 credit assignment 或 optimizer 也只会更有效地学错。它也为 Deep Research 的引用充分性、证据边界和无法回答场景提供了可机器检查的 adversarial benchmark 结构。

## 可迁移启示

- 生成 rubric 时要把任务指令与证据约束分开；“遵循输出格式”不能覆盖“证据不足时必须拒绝推断”。
- 上线 rubric reward 前，应让攻击者显式读取 rubric 做 best-of-N 或 adversarial search，并用独立 certificate 检查高分答案是否越界。
- 只看 rubric-judge agreement 不够；需要同时报告攻击模型、judge、Oracle、rubric 抽样次数和 verifier sensitivity。
- 对 Deep Research 可把“引用存在”升级为“引用是否实际支持该主张”，并为证据不足、来源冲突、无法穷尽等任务建立对称 certificate，避免模型朝任一方向过度断言。

## 局限

- 论文评测 rubric 生成器，没有执行实际 RL；exploit rate 不能直接等同于 policy 训练后的 reward hacking 发生率。
- Hard-45 是按参考模型失败筛出的压力集，存在选择放大；主结果应以 Full-150 为准。
- Oracle、certificate 和固定诚实基线都可能出错；同一批答案换 Oracle 后结果差异很大，且人类校准只有一名作者和 40 个样本。
- 主实验多为每个环境一次 rubric 抽样；重复采样显示结论存在较大随机性。
