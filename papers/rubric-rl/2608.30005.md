# Small Language Models as Judges for Rubric-Based Reinforcement Learning

- **arXiv**: [2608.30005](https://arxiv.org/abs/2608.30005)
- **版本 / 日期**: v1，2026-08-30
- **作者**: Fengyu Xie、Yilun Zhao、Bingsen Chen、Arman Cohan、Chen Zhao
- **机构**: New York University；Yale University
- **主方向**: `Rubric RL`
- **辅助标签**: `small-judge`、`probe-judge`、`GRPO`、`reward-modeling`、`criterion-level`
- **阅读状态**: Review Run 精读

## 一句话结论

用 Qwen3-1.7B 的线性 probe 读取隐藏表示，比直接生成判词的 Qwen3-8B judge 更适合做 rubric reward：在相同 GRPO 训练协议下，RaR-Science rubric 分数从 0.232 提升到 0.643，而 8B 生成式 judge 只有 0.594，累计判分时间却多 10.7 倍。

## 问题

Rubric-based RL 可以训练没有精确答案或规则 verifier 的开放式任务，但每个 rollout 都要按实例级标准反复评分。若用 7B 以上模型生成完整判词，奖励成本和延迟会成为 RL 的瓶颈；若用更小模型，又可能无法可靠区分“满足/不满足某条 criterion”。论文研究：小模型能否直接提供稳定、便宜且可迁移的 criterion-level reward？

## 大白话解释

把回答质量想成一张检查表：是否回答了问题、证据是否充分、解释是否正确。生成式 judge 会为每一项写一段“为什么”，慢且容易格式出错；probe judge 不生成文字，而是读取小模型某一层的隐藏向量，用一个很小的分类头直接预测每项是否满足。GRPO 只需要这些概率来比较同一问题的多个回答，不需要每次调用大模型写评语。

## 具体例子

对一个要求解释科学结论并给出证据的回答，rubric 可能包含“结论正确”“机制解释完整”“证据与结论相关”三项。Qwen3-1.7B probe 为三项输出满足概率并聚合成 reward；若回答只给出正确结论但没有机制解释，第二项的低概率会拉低总 reward。生成式 8B judge 则需逐项生成 verdict，再解析成同样的信号。

## 方法拆解

1. **构造可测任务**：建立 PointRubric 与 RaR-Science-Static 两个 pointwise rubric 数据集，每个回答都有实例级 criterion 和逐项满足标签。
2. **比较三种小模型读出**：生成式 verdict、Yes/No token 的 logprob margin，以及从 Qwen3 隐藏表示训练的 Probe judge。
3. **选择 probe 架构**：主配置是 Qwen3-1.7B 的线性 last-token probe；100 个训练问题即达到 0.805 macro-F1，1,000 个问题达到 0.834。MLP 和末四层平均只带来小幅变化，mean pooling 明显更差。
4. **接入 GRPO**：固定 Qwen3-4B-Base actor、RaR-Science 训练集、优化器、响应预算、rubric 聚合和外部 GPT-4o 评测，只替换 reward judge。probe 输出 criterion 概率，作为 GRPO 的在线奖励。
5. **检查迁移**：在 GPQA-Diamond 上测试策略迁移，并让只用 RaR-Science 标签训练的 probe 直接评估 RaR-Medicine，检验 reward 结构是否跨任务和领域保留。

## 实验与证据

- **训练 / 评测模型**：静态 judge 主要比较 Qwen3-1.7B、4B、8B 的 probe/readout；在线 RL 使用 Qwen3-4B-Base actor。对照 reward 是 Qwen3-8B Generative judge；策略质量由 GPT-4o rubric 评分，另有人工审计。
- **Benchmark / 数据**：PointRubric、RaR-Science-Static 用于 criterion-level judge 评测；RaR-Science 用于 GRPO；迁移评测使用 198 道 GPQA-Diamond 问题和 RaR-Medicine rubric。主 RL probe 分别用 450 个训练回答、50 个开发回答拟合。
- **基线**：Qwen3-8B 生成式 judge；小模型的 verdict 与 Yes/No logprob readout；固定 actor 和训练协议下的 reward-model 对照。
- **指标**：criterion-level agreement / macro-F1、RaR-Science rubric score、GPQA-Diamond accuracy、跨领域 macro-F1、累计 reward-judge time、RL elapsed time，以及人工与 GPT-4o 偏好一致率。
- **主要证据**：Qwen3-1.7B probe 在静态任务中整体优于同规模生成式和 logprob readout；在线 RL 的累计判分时间为 2.33 小时，8B 生成式 judge 为 24.98 小时。两者 RL elapsed time 分别为 8 小时 51 分 47 秒和 11 小时 11 分 56 秒。

## 实验结果总结

- 在匹配的 GRPO 协议中，Qwen3-4B-Base 使用 Qwen3-1.7B probe 后，RaR-Science rubric score 从基线 actor 的 0.232 升到 0.643；使用 Qwen3-8B generative reward 只到 0.594。
- Probe policy 在 GPQA-Diamond 上把 accuracy 从 0.335 提高到 0.388，说明策略收益不完全局限于原来的科学 rubric 格式。
- 只在 RaR-Science criterion 标签上训练的 1.7B probe，在未用 RaR-Medicine 标签拟合的情况下达到 0.718 macro-F1，表明 criterion-level 表示有一定跨领域迁移性。
- 100 个样本已足以让线性 probe 达到 0.805 macro-F1；更大的 probe 并不必然带来更高 RL 收益，作者观察到大 probe 可能把 actor rollout 的奖励打得过于饱和，降低 GRPO 组内差异。
- 100 个样本的人类偏好审计中，probe policy 被偏好 72 次；GPT-4o 偏好 80 次。剔除平局后，人类与 GPT-4o 在 72 个案例中的 69 个判断一致（95.8%）。

## 与现有方向的关系

这篇工作属于 Rubric RL 的 reward-model efficiency 路线：它不重新设计 GRPO，而是把昂贵的生成式 judge 换成隐藏表示上的轻量 probe。与 OpenRubrics 等工作关注 rubric 生成不同，它关注 rubric 已给定时如何低成本地产生 criterion reward；与 Credit Assignment 的 token/step 反馈不同，它仍主要提供回答级、criterion-level reward。对 Harness RSI 或长程 agent 训练而言，probe 可作为低延迟的在线筛选器，但尚未直接验证多轮工具轨迹。

## 可迁移启示

- 奖励模型不一定需要生成可读解释；若训练目标只需要 criterion 概率，隐藏表示 probe 可能是更合适的接口。
- 选择 judge 应看下游 policy improvement，而不能只看固定 response bank 的 F1；较大的 judge 可能因 reward saturation 反而不利于 GRPO。
- 小规模 criterion 标签足以训练有效 probe，但仍应保留跨领域、外部 judge 和人工审计，避免把 probe 的分数当成真实质量。
- 对 Deep Research，可把 citation support、证据相关性和结论完整性分别作为 criterion，让 probe reward 在检索循环中低成本运行。

## 局限

- RL 主实验集中在 RaR-Science 和 Qwen3-4B actor，尚未证明 probe 在长程多轮 agent、工具调用或多模态 rubric 上同样可靠。
- GPT-4o 是主要外部策略评测器；人工审计规模较小，不能替代大规模独立人评。
- Probe 需要带 criterion 标签的监督数据，且跨任务迁移仍可能受 rubric 语言、领域和分布影响。
