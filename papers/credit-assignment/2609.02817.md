# Cliff: Learning Process Rewards from the First Mistake

- **arXiv**: [2609.02817](https://arxiv.org/abs/2609.02817)
- **版本 / 日期**: v1，2026-09-02
- **作者**: Peixuan Han、Runhui Wang、Ketan Ramaneti、Jie Hao、Gerald Friedland、Chris Kong
- **机构**: Amazon Web Services；University of Illinois Urbana-Champaign
- **主方向**: `Credit Assignment`
- **辅助标签**: `first-mistake`、`process-reward`、`RLVR`、`GRPO`、`token-level-advantage`
- **阅读状态**: Review Run 精读

## 一句话结论

Cliff 让离线教师只定位每条 rollout 的第一个错误（Pitfall Step），把轨迹切成正确前缀和错误后缀，再转成 token-level advantage；12 个数学与编程场景中稳定优于 GRPO、教师辅助 GRPO 和 on-policy distillation。

## 问题

RLVR 通常只有最终答案对错，近乎正确的长推理与完全错误的尝试收到同样更新。过程奖励模型需要额外训练且易 reward hacking；on-policy distillation 依赖师生模型共享推理模式。问题是：不训练新 reward model，怎样给长轨迹提供足够细的信用分配？

## 大白话解释

一条解题过程在第三步首次算错，后面所有步骤都建立在坏前提上。Cliff 不必逐步给后面每句判分，只需找出“悬崖边”这一步：错误之前的 token 保留较正面的信号，错误及之后沿用负结果信号。这样比把一个总分均匀撒满整条回答更能告诉模型该改哪里。

## 具体例子

学生先正确列出方程，随后把负号抄错，最后算出错误答案。自动 verifier 只返回 0 时，GRPO 会惩罚整段；Cliff 的教师把“负号抄错”标为 Pitfall Step，方程建立部分不被误罚，错误后缀受到负反馈。若教师参考解未通过 verifier，该组回退 vanilla GRPO。

## 方法拆解

1. **参考解过滤**：教师先为问题生成参考解；只有自动 verifier 判定正确时，才用于判断学生 rollout。
2. **Pitfall Step 识别**：教师判断学生答案对错；错误时定位推理首次变错的句子索引。超长截断 rollout 直接设为 `p(a)=0`。
3. **前缀/后缀优势**：正确 rollout 使用标准 `A_cor`；错误 rollout 在 `p(a)` 前使用 `lambda A_cor - b`，从 `p(a)` 起使用负的 `A_inc - b`，再以 `b` 重心化使组内 token advantage 均值为零。
4. **简洁超参**：主实验 `lambda=0`，避免通过无意义延长正确前缀来 hack reward；教师 rollout temperature 为 0.6。
5. **兼容 GRPO**：不改 group-relative advantage 或 clipping，只在 token 粒度重分配已有结果信号；教师与学生可不同模型、不同 tokenizer。

## 实验与证据

- **训练 / 评测模型**：学生为 Qwen3-4B-Base（先在 OpenThoughts 上 SFT）与 Phi-4-mini-Instruct；教师为 SOTA（论文未指明具体名称）、Qwen3-32B、Gemma3-27B。训练基于 veRL，4 张 H100 80GB 或 B200 192GB。
- **Benchmark / 数据**：数学训练集 DAPO-math-17k-processed（13,116 条），评测 GSM8K（1,319）、MATH-500（500）、DAPO（1,000）、AIME（933）；编程训练集 DeepCoder（13,485，表中原文如此），评测 CodeContests（400）、LiveCodeBench（611）、DeepCoder（500）。代码任务仅当 10 个测试用例全部通过才给 1 分。
- **基线**：自动 verifier 的 vanilla GRPO；教师只判最终对错但整段共享 advantage 的 GRPO with Teacher；教师 rollout 蒸馏；on-policy distillation（OPD）。
- **指标**：各 benchmark accuracy / pass rate；数学四集平均（Avg.），编程三集平均；教师质量另报 reference accuracy、judge accuracy、Pitfall Step 与人工标注的平均句距 `p-dis`。
- **教师判错证据**：从 DAPO-Math 抽取 50 条正确、50 条错误 rollout 做人工标注。SOTA 教师 judge accuracy 91%，平均 `p-dis` 1.23 句，82% 样本句距不超过 1；Qwen3-32B judge accuracy 91%（给定真值参考解），Gemma3-27B 为 93%。

## 实验结果总结

Cliff 在两名学生、三类教师和数学全部设置中取得最高平均分，编程大多数设置领先，Phi-4-mini + SOTA 教师编程几乎持平。以 Qwen3-4B + SOTA 教师为例，数学平均 65.66（GRPO 62.37），编程平均 25.96（GRPO 24.83）；Qwen3-4B + Qwen 教师数学 64.62、编程 26.02，仍高于 GRPO 的 61.20、25.52。Phi-4-mini + SOTA 教师数学平均 51.73（GRPO 49.86），编程 24.93（GRPO 24.94）。论文摘要概括跨 12 个场景相对 OPD 提升 15%、相对标准 GRPO 提升 7%。

消融显示“有教师”本身不是主要收益：GRPO with Teacher 仅较 vanilla GRPO 小幅变化，而显式 Pitfall Step credit assignment 带来最大提升。`lambda=0` 在 GSM8K/MATH-500/DAPO/AIME 平均 65.66；`lambda=1` 降至 63.98，平均长度从 1,506 增至 1,959，说明正向奖励错误前缀会诱发 length hacking。去掉真值过滤后，强教师几乎不降，较弱教师约降 2%，但仍常优于 vanilla GRPO。

## 与现有方向的关系

Cliff 是 Credit Assignment 的“首错边界”路线：比 token/step 级 PRM 更便宜、更少标注，比 OPD 不要求师生同族或共享 tokenizer，比 outcome-only GRPO 提供过程信号。它与 Rubric RL 的共同点是把终局结果拆细，但 Cliff 使用错误位置而非多 criterion rubric；也可作为 Harness RSI 中执行轨迹的轻量训练接口。

## 可迁移启示

- 长程 agent 轨迹可能只需定位首个致命错误，不必让 judge 为每个后续动作编造细粒度分数。
- 保留自动 verifier 作为参考解过滤器；无 verifier 时可用强教师，但需监控参考解错误传播。
- 报告 judge 的定位误差与训练收益，不能只报最终 accuracy。
- token advantage 重心化、超长截断和 `lambda=0` 是抑制长度投机的关键安全阀。

## 局限

- 依赖教师判断首错；远距离相互作用、多个同时错误或有效但不同的推理路径可能导致定位歧义。
- 主实验仍使用自动 verifier 过滤教师参考解；真实开放任务往往没有同等可靠的 ground truth。
- 任务以单轮数学与算法编程为主，尚未覆盖工具调用、多轮环境交互、多模态证据或长程 Deep Research。
- 论文未提供独立项目仓库；实现基于 veRL，公开代码链接待核对。
