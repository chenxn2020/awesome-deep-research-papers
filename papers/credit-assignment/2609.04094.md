# DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics for Long-Horizon Agent Training

- **arXiv**: [2609.04094](https://arxiv.org/abs/2609.04094)
- **版本 / 日期**: v1，2026-09-03
- **作者**: Shubham Gandhi；Saurabh Goyal；Kiran Kate；Yara Rizk
- **机构**: Carnegie Mellon University；IBM Research
- **主方向**: `Credit Assignment`
- **辅助标签**: `dynamic-rubrics`、`step-credit`、`outcome-blind-rl`、`long-horizon-agents`
- **阅读状态**: 全文精读

## 一句话结论

DRACO 不读取任务成功标签，而是动态生成会随策略失败模式变化的 rubric，再把 trajectory 级 judge 分数按 criterion 引用的责任步骤重新分配；在 Qwen3.6-27B 上把 AppWorld test-normal 的 TGC / SGC 从 69.4 / 41.1 提升到 85.3 / 70.6。

## 问题

长程 agent 的最终结果通常只有一个稀疏分数。vanilla GRPO 会把同一个 trajectory advantage 乘到整条轨迹的每个 token 上，于是正确搜索、错误 API 调用和无关冗长输出得到同样方向和强度的更新。许多现实任务又没有可靠 verifier，无法直接用单元测试或标准答案产生 outcome reward。

## 大白话解释

一名 agent 连续做了十步才完成任务，其中第七步选错工具、后面几步又把错误补救回来。只给最终结果会让十步一起受奖或受罚。DRACO 先列出这次任务真正需要满足的检查项，再让 judge 指出每项由哪些步骤支撑或破坏，把有限的总奖励集中到负责任的步骤，而不是平均撒给整段轨迹。

## 具体例子

假设一个银行 agent 要查询账户、选择收款人、核对金额并执行转账。某条轨迹正确查询了账户，却在转账前没有确认收款人。动态 rubric 可以保留“正确读取账户状态”和“转账前确认收款人”两个有区分度的 criterion；judge 将前者引用到查询步骤并判通过，后者引用到执行步骤并判失败。正优势轨迹主要强化高通过率步骤，负优势轨迹主要压低高失败率步骤，未被引用步骤继承已引用步骤的平均质量。

## 方法拆解

1. 对每个任务先根据指令生成 rubric，再从同组每条 rollout 中补充暴露出的子目标和失败模式，合并去重。
2. 使用 discriminative dropout 删除整组 trajectory 全部通过的 criterion，只保留当前策略仍能从中获得区分信号的项。
3. 冻结 judge 对每条 trajectory 的每个 criterion 输出 pass、fail 或 not applicable，同时引用负责任的 agent step。
4. 用 `(pass - fail) / (pass + fail)` 得到 trajectory reward，在组内标准化为 GRPO advantage。
5. 每个步骤的质量是引用它的 criterion 中通过项占比；winner 强化高质量步骤，loser 抑制低质量步骤。
6. 闭式重分配保持 trajectory 的总 advantage 不变，并按步骤 token 数归一化，避免冗长步骤仅因 token 更多而获得更大总更新。gap token 不参与分配；没有任何步骤引用时回退到 vanilla GRPO。

## 实验与证据

- **训练 / 评测模型**: Qwen3.6-27B（全部消融）和 Qwen2.5-32B-Instruct；均以 LoRA + GRPO 训练。训练期 rubric 生成、合并、评分与 attribution 统一使用 GPT-5.4（temperature 0.1）；另评估 Qwen3.6-27B self-judge。
- **Benchmark / 数据**: 只在 AppWorld train 的 90 个任务训练；评测 AppWorld test-normal 168 题、test-challenge 417 题和零样本迁移的 τ-bench Banking 97 题。AppWorld 覆盖 9 个 app、457 个 API。
- **基线**: 未训练 base；使用 AppWorld 单元测试结果的 outcome-reward GRPO；静态 rubric／无 step credit 的三个 DRACO 消融；Qwen2.5-32B 上的 outcome-aware SALT；random reward；若干未在 AppWorld 训练的前沿模型只作推理时成本对照。
- **指标**: AppWorld Task Goal Completion（TGC）与 Scenario Goal Completion（SGC）；τ-bench state-matching Success Rate（SR）；三次运行的 `pass@k` 与要求全部成功的 `pass^k`；平均 agent turns 和 API 估算成本。
- **训练设置**: batch size 16，每题 GRPO group size 6，8 张 H100；Qwen3.6-27B 训练 100 steps / 20 epochs，Qwen2.5-32B 训练 75 steps / 15 epochs；每个设置取最后三个 epoch checkpoint 的均值，每个 checkpoint 独立评测三次。

## 实验结果总结

Qwen3.6-27B 上，DRACO 将 AppWorld test-normal 的 `p¹` TGC / SGC 从 69.4 / 41.1 提升到 85.3 / 70.6，分别增加 15.9 和 29.5 点；test-challenge TGC 从 49.7 升至 61.5；未在 τ-bench 训练仍把 Banking SR 从 15.8 提升到 20.4。相同超参数下，它在 test-normal 比 ground-truth outcome reward 高 5.3 TGC、11.3 SGC。

收益在一致性上更明显：test-normal 的 `pass³` TGC 从 47.6 升到 72.8，而 `pass@3` 只增加 3.9 点，说明训练主要把偶尔成功变成重复运行也成功。Qwen2.5-32B 上，test-normal TGC / SGC 从 35.7 / 17.3 升至 62.9 / 42.3，接近使用真实结果的 SALT 66.2 / 47.9。

完整 DRACO 的跨任务平均 `p¹` 为 55.7，高于无动态 rubric 的 52.0、无 step credit 的 53.3，以及两者都无的 52.7。self-judge 版本平均 `p¹` 为 52.1，低于 GPT-5.4 judge 的 55.7；因此方法可减少但尚未消除对强外部 judge 的依赖。

## 与现有方向的关系

DRACO 同时连接 Rubric RL 与 Credit Assignment，但核心新增点是把 criterion 判断映射回责任 step，并保持原 trajectory advantage 总量不变。相比只生成更好 rubric 的方法，它明确改变梯度落点；相比 Information Gain 等无 judge 的 turn reward，它能覆盖没有 verifier 的开放式长程任务，但付出外部 judge 成本。

## 可迁移启示

- rubric 不应固定为离线模板；让当前 rollout 暴露新失败模式，再只保留仍有区分度的 criterion。
- criterion 评分时同步产出证据步骤，能让同一次 judge 调用同时承担 reward 与 attribution。
- credit 重分配应守恒总 advantage、保持正负号，并消除步骤长度带来的隐式权重。
- 同时报 `pass@k` 和 `pass^k`，避免把“偶尔能做对”误读成稳定能力。

## 局限

- 训练数据只有 90 个 AppWorld 任务，虽然 test-challenge 与 τ-bench 有迁移收益，领域覆盖仍有限。
- 动态 rubric、评分和步骤引用都依赖 judge；错误 attribution 或 rubric 遗漏会直接改变梯度。self-judge 结果仍弱于 GPT-5.4 judge。
- 论文把 ground-truth outcome 严格留在评测，但训练计算和 judge 调用成本较高；收益能否扩展到更长轨迹和更大训练集待验证。
- judge 引用的是 agent turn / code block 级步骤，不是工具调用内部或 token 级因果贡献，相关步骤也不等于真正的反事实责任。
