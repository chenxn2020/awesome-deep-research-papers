# On the Navier–Stokes Millennium Prize Problem

- **版本 / 日期**: OpenAI 官方研究博客，2026-09-08；并发工作说明更新于 2026-09-10
- **作者**: OpenAI
- **机构**: OpenAI
- **主方向**: `Blogs / Harness RSI`
- **辅助标签**: `multi-agent-research`、`formal-verification`、`scientific-discovery`、`large-scale-orchestration`
- **阅读状态**: 官方博客精读；数学证明本身未做独立同行评审核验

## 一句话结论

OpenAI 报告称，一个由约 10,000 个并发 agent 组成、会共享中间结果并接受人工资源调度的研究系统，在约 88 小时内提出了 Navier–Stokes 有限时间奇性构造，随后用 GPT-6 Astra 花 17 小时完成 Lean 形式化；该案例显示，大规模并行、结果汇聚、任务重分配和形式验证可以组成可审计的自动研究闭环。

## 问题

三维不可压缩 Navier–Stokes 方程从光滑初始状态出发时，速度是否可能在有限时间内变得无界，是 Clay 数学研究所的千禧年难题之一。自动研究层面的附加问题是：怎样让大量 agent 在巨大搜索空间中探索不同证明路线，同时筛选、共享和严格验证少数有希望的结果。

## 大白话解释

这不是让一个模型一次写完证明，而是让许多研究小组同时尝试不同路线。某组先解决较接近的 Euler 方程问题后，系统把该线索传播给更多小组，再把算力集中到最有希望的 Navier–Stokes 路线。候选证明最后还要转成 Lean 代码，让证明检查器逐步核对，而不是只凭模型自评。

## 具体例子

系统先给不同 agent 组分配官方问题的 A、B、C、D 四类表述，并另设较容易的相关问题。近 100 个 agent 用约 50 小时得到无外力 Euler 正则性反例后，OpenAI 将其他问题上的 agent 转向 Navier–Stokes，并用 Codex 汇总各组最有用的中间结论供后续组继续探索。最终方案构造一个向内螺旋并沿轴向拉伸的涡旋，使速度在有限时间发散，但能量保持有限、外力仍光滑。

## 方法拆解

1. 把同一数学问题的多种官方表述分给不同并行 agent 组，保留路线多样性。
2. 同时探索更容易但结构相近的子问题，用子问题突破判断主问题是否值得集中资源。
3. 允许组内沟通，并用 Codex 汇总跨组中间成果，形成可复用的共享研究上下文。
4. 人类依据阶段性结果重新分配 agent，并在训练中的更新版内部模型可用后替换执行模型。
5. 将分析证明转写为 Lean 形式化，由内核检查证明项；对运行过程保持监控与隔离。

## 实验与证据

- **训练 / 评测模型**: 主要研究 agent 使用仍在训练、官方称显著强于 GPT-6 Astra 的内部模型，具体名称、参数规模和训练配方待核对；Lean 形式化与验证使用 GPT-6 Astra。
- **Benchmark / 数据**: 不适用。任务来自 Clay 数学研究所的 Navier–Stokes 官方问题表述，并包含相关 Euler 正则性子问题；agent 可读取缓存互联网并运行代码。
- **基线**: 不适用。博客没有给出单 agent、无共享、无任务重分配或其他模型的受控对照。
- **指标**: 是否产出完整分析证明与 Lean 形式化；墙钟时间、agent 数量、消息数和输出 token 数。证明的外部同行评审或 Clay 正式认定尚未给出。
- **规模**: 产生 Navier–Stokes 结果的组约有 10,000 个并发 agent；从启动到得到解析结果约 88 小时，Lean 阶段另用 17 小时。全部尝试共 490 万条消息、约 3,000 亿输出 token；Navier–Stokes 部分为 270 万条消息、约 1,300 亿输出 token。

## 实验结果总结

官方材料称，系统构造了一个从静止、光滑初态出发，在光滑外力作用下于有限时间形成奇性的解，同时全程保持有限能量；OpenAI 将其对应为官方问题中的 C、D 命题，并公开了解析写作与 Lean 形式化。

研究过程还得到一个无外力 Euler 正则性反例，成为集中攻关 Navier–Stokes 的关键中间信号。博客报告的是单次重大案例，不足以估计系统在任意开放数学问题上的成功率，也没有隔离大模型能力、并发规模、人工调度、共享上下文和形式验证各自贡献。

## 与现有方向的关系

该案例属于 Harness RSI 的系统级观测，而不是 harness 自动更新算法。它与自动化研究员和 OpenAI 内部研究加速报告共享并行 agent、持久中间产物、结果汇聚、人工门控与外部验证等组件；新增证据是这些组件可扩展到约万级并发，并把形式证明器作为最终验收层。系统根据中间突破改写后续任务分配和共享上下文，但博客未说明 harness 本身是否通过训练或自动晋升持续演化。

## 可迁移启示

- 为开放研究任务同时维护主问题和结构相近的子问题；子问题突破可充当资源重分配信号。
- 大规模并行只有配合跨组成果压缩与再分发才有价值，否则消息量不会自动变成共享进展。
- 让探索模型负责提出候选，让形式系统或可执行测试负责最终验收，避免模型自评成为唯一质量门。
- 记录墙钟时间、消息数、token、并发规模和人类干预点，才能区分能力提升与纯算力扩张。

## 局限

- 结论来自 OpenAI 官方博客及其公开证明材料，本条目没有独立复核数学证明，也没有外部同行评审或 Clay 数学研究所认定。
- 内部研究模型未公开，训练数据、训练方法、agent 提示、组内协议、失败路线和完整运行日志均待核对，结果难以复现。
- 没有消融实验，无法判断万级并发、模型更新、人工调度、Codex 汇总和 Lean 验证各自贡献。
- 约 1,300 亿输出 token 的单题成本很高；这种规模对一般科研任务的经济性与环境成本未报告。
