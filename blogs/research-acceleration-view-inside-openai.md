# Research Acceleration: The View Inside OpenAI

- **版本 / 日期**: OpenAI Research，2026-09-06
- **作者 / 机构**: OpenAI
- **主方向**: `Blogs / Harness RSI`
- **阅读状态**: 全文精读

## 一句话结论

OpenAI 的内部观测显示 coding agent 使用量、实验量和长任务成功率同时上升，研究组织在 2026 年 8 月中旬已使用每个人类工作日 3.1 个 agent-workdays；但这些指标仍不能单独证明总体研究进度等比例加速。

## 问题

“agent 加速研究”常被简化成 token、代码量或运行时增长，但 AI 研发是一条由选题、设计、实现、训练、评测、分析和决策串联的瓶颈链。报告尝试回答：内部 coding agent 使用如何变化、研究产出和成功率是否同步变化、哪些环节仍需要人工介入，以及安全限制如何改变实验资源分配。

## 大白话解释

给研究团队更多自动化助手，不等于研究速度按助手工作时长线性增长。助手可能让代码和实验跑得更快，但选什么问题、怎样判断结果、何时暂停仍可能成为新瓶颈。报告因此同时看使用量、实验活动、任务难度、成功率和人工干预，而不是只看生成了多少代码。

## 具体例子

对估计需要人类 4–8 小时的成功任务，最近六个月超过一半仍包含至少一次人工干预。这说明“能完成几天级明确任务”的 automated research intern 更接近受监督执行者：人类仍需提供方向、纠偏和验收，而不是把开放式研究目标交出后完全退出。

## 方法拆解

- 汇总研究组织内部 coding agent 用量，并把 agent 工作折算为 8 小时制 agent-workdays。
- 跟踪活跃实验者的人均实验数，并与 Codex 采用变化对照；报告明确提示同期可用算力也增长，不能据此作单因果归因。
- 用 Epoch AI 的研发任务分类，把 token 分入 Decide、Design、Build、Run、Analyze、Communicate 六阶段。
- 用 agentic classifier 估计有人类时间真值和结果标签的任务难度、成功与干预；排除结果不确定以及样本或独立用户少于 50 的点。
- 观察安全事件后的 RL 训练停机、环境加固和不同模型算力替代，分析安全约束如何重排而非简单消除实验活动。

## 实验与证据

- **训练 / 评测模型**: 不适用；对象是 OpenAI 研究组织使用的 coding agent 与 Astra-class 等内部研究工作负载，具体模型组合未完整公开。
- **Benchmark / 数据**: 内部 agent 使用日志、agent 运行时、实验活动、技术支持频道、可获得结果真值的研究任务，以及 RL GPU allocation；完整样本规模待核对。
- **基线**: 2026 年初到 8 月的时间序列；安全限制前后；不同任务预计人类耗时分桶。
- **指标**: 每用户 API 价 token 支出、agent-workdays / human-workday、人均实验数、任务类型 token、成功率、人工干预率和 GPU allocation。
- **主要结果**: 8 月中旬研究组织每个人类工作日使用 3.1 个 agent-workdays；中位研究员每日 agent 用量按 API 价格超过 600 美元，90 分位超过 7,000 美元。1–7 月多个难度桶的成功率总体上升，但 4–8 小时成功任务中过半仍需人工干预。

## 实验结果总结

agent 使用已从辅助编码扩展到技术支持、监控和更长周期任务，且 2026 年 8 月活跃实验者人均实验数达到自 2025 年 1 月跟踪以来最高值。报告把这些变化视为“与研究加速一致”的证据，不声称已经测出净因果效应。

安全限制提供了另一组观察：7 月 20 日研究容器服务曾暂停并加固，最新部署模型的 RL 训练暂停两周；8 月 7 日对 Astra 施加更强限制后，下一周 Astra-class GPU allocation 又下降 59.2%，其他模型增长 17.2%，抵消约 85% 的 Astra 降幅。算力会转移到仍允许的任务，因此单看总算力很难衡量限制对前沿进展的真实影响。

## 与现有方向的关系

该报告为 Harness RSI 提供组织级观测框架：既测 agent 执行能力，也测人类干预、研究吞吐和安全门控。它补充论文 benchmark 的实验室设置，但没有公开可复现任务集，不能替代 EvoHarness-RL、LoopArena 等受控对比。

## 可迁移启示

- 同时记录 agent 时间、任务成功、人工干预和最终研究产出；token 与代码量只能作为活动指标。
- 用研发阶段分类定位新瓶颈：Build / Run 变快后，Decide、评审和算力可能成为限制项。
- 安全控制评估要追踪工作负载替代效应，不能把受限模型算力下降直接当作总研究速度下降。
- 长任务评价应明确人类干预次数；“最终成功”不等于 agent 独立完成。

## 局限

- 数据来自单一机构，工具、人才、算力和内部流程都不具代表性。
- Codex 使用、实验量和成功率共同上升是相关关系；算力、模型能力和团队变化均为混杂因素。
- 只覆盖多数但非全部 agent 使用；任务成功分类只分析有可靠结果标签的子集，完整样本量和 classifier 校准细节待核对。
- “automated research intern”是 OpenAI 自定义能力门槛，不等同于独立完成开放式研究，也不是跨机构标准 benchmark。
